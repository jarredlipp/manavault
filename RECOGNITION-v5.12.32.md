# ManaVault v5.12.32 — Indexed recognition accuracy

This update keeps the **entire v5.12.31 feature set, source tools and tests**, the native CameraX/ML Kit scanner, existing storage key `manavault-v1`, the full-artwork SQLite database updater and the unchanged printing index schema. It does not remove files or collection/deck features.

## Actual changes

1. **Offline indexed artwork name rescue.** The complete artwork DB now tries its original strict hash-band query first. Only if that fails or scores poorly does it generate additional one-bit-per-band and four small-offset art-crop probes. Candidate retrieval still uses the SQLite `(band,code)` index, not a 120,000-card linear artwork scan. This is an advisory name shortlist, *not* direct authority to save any printing. An OCR-unreadable title still requires strict score/margin gating and independent physical-printing verification.
2. **Frame alignment for card-name-scoped printing comparison.** After identifying a title, the full-index matcher can compare four slightly shifted artwork-only descriptors, with an alignment penalty. It leaves title, rules/text, type line and footer descriptors in their original locations so that equal illustration with distinct collector/footer or text-box detail is not collapsed.
3. **Candidate-scoped collector OCR.** When the card's name has printable candidates, those known collector numbers are sent to the native footer reader. If fast OCR doesn't read one of the candidates, the reader attempts **one** enhanced, enlarged crop focused on the lower-left/old-frame footer. It supplies OCR lines to the existing printing-evidence resolver and does not select a printing itself. Copyright years and arbitrary text are not accepted as credible collector evidence by the native rescue trigger.
4. **Co-located expansion-symbol competition.** The native icon matcher compares the winning and competing set-icon shapes on the *same photographed crop*. Ambiguous same-location glyphs cannot verify an edition, even if their independent best matches came from different places on the card. The existing global score/margin and physical set/collector rules remain active.
5. **Better manual printing picker ordering.** When artwork alone cannot distinguish printings sharing an illustration, the candidate-specific SQLite text/footer/layout ranking may order manual choices. Printed set and collector matches take precedence. No automatic selection is based on advisory visual ordering.
6. **Tests and build safety.** New pure-Java OCR/hash-probe classes are included **in both** the full source ZIP and targeted patch; corresponding JVM/SQLite and JavaScript set-ambiguity checks run in GitHub Actions before APK compilation.

## Verification and performance limitations

- Existing 21 regression commands + new v5.12.32 checks pass locally. Additional `FullArtworkIndex` compilation with Android API stubs passes. A **real Android Gradle build, antivirus scan and phone-camera benchmarking are not available locally** and are not claimed.
- The complete offline artwork index is an independent download generated by `Build full printing artwork database`; the 1,200 reference seed remains the fallback until the full index is installed. It is essential to install that index for the new SQLite candidate-retrieval path.
- This is a conservative accuracy improvement, not a claimed 20 cards/min or 99% benchmark. Fuzzy lookup can take longer **only on hard OCR misses**; focused footer OCR can add extra work **only when plausible collector numbers were not seen**. Camera scene-change and frame latency require real-device follow-up profiling.
- Different printing IDs with identical pixels cannot be visually disambiguated: scan set code, collector, rarity, text box, or ask for manual selection. The scanner must not guess an exact edition from artwork alone.
